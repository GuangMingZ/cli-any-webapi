# /cli-any-webapi sync

Incrementally re-sync an existing generated CLI package with updated source code or API logs. Adds new endpoints, deprecates removed ones, and refines types — without discarding manual changes.

## Usage

```bash
/cli-any-webapi sync <cli-path> [--source <source-path>] [--logs <log-file>]
```

## Arguments

| Argument | Required | Description |
|----------|----------|-------------|
| `cli-path` | Yes | Path to the existing generated CLI package directory |
| `--source <source-path>` | Recommended | Path to the (updated) Web system source code directory |
| `--logs <log-file>` | Optional | Path to updated API request log file. Supported formats: HAR (`.har`), CSV (`.csv`), JSON Lines (`.jsonl`), JSON array (`.json`) |

At least one of `--source` or `--logs` must be provided.

## Examples

```bash
# Sync after backend code changes
/cli-any-webapi sync ./my-app-api-cli --source ./my-app

# Sync after capturing new API logs
/cli-any-webapi sync ./my-app-api-cli --logs ./new-api-logs.har

# Full sync with both source and logs
/cli-any-webapi sync ./my-app-api-cli --source ./my-app --logs ./api-logs.csv
```

## What this command does

> **Critical**: This command must NOT destroy manual changes users have made to `src/config.ts`, `package.json` scripts, or any non-generated files. It only modifies auto-generated files.

### Step 1 — Load previous state

- Read `TEST.md` Part 1 from `cli-path` to get the previous endpoint list
- Identify which files are auto-generated (they have the `// Auto-generated by cli-any-webapi` header)

### Step 2 — Re-run discovery (if --source provided)

- Execute Phase 1 from HARNESS.md against the updated source
- Produce a new endpoint list

### Step 3 — Diff endpoints

Compare new endpoint list with previous list:

**New endpoints** (in new list, not in old):
- Generate new type interfaces and command code
- Mark with `// Added: <ISO date>`

**Removed endpoints** (in old list, not in new):
- Comment out the corresponding command in `src/commands/<module>.ts`
- Mark with `// DEPRECATED: <ISO date> — endpoint removed from source`
- Do NOT delete type interfaces (they may still be referenced)

**Unchanged endpoints**:
- If `--logs` provided, update type shapes (may add optional fields, never remove required ones)
- Mark updated fields with `// Updated: <ISO date>`

### Step 4 — Re-run log analysis (if --logs provided)

- Execute Phase 2 from HARNESS.md
- For each endpoint where type has changed:
  - If a field becomes required (was optional): add comment `// Promoted to required: <date>`
  - If a new optional field discovered: add to interface as `optional`
  - If field type changes: convert to union type `OldType | NewType`

### Step 5 — Rebuild and validate

```bash
cd <cli-path>
npm run build
node dist/index.js --help
```

### Step 6 — Update TEST.md and SKILL.md

- Update `TEST.md` Part 1 with new endpoint table
- Append a sync log entry to `TEST.md`:

```markdown
## Sync Log

### <ISO date>
- Added: X endpoints
- Deprecated: Y endpoints
- Type updates: Z endpoints
```

- Regenerate `SKILL.md` sections for changed modules

## Success Criteria

- [ ] No manual changes lost
- [ ] Deprecated commands are commented, not deleted
- [ ] New endpoints have matching CLI commands and types
- [ ] Build succeeds
- [ ] `TEST.md` sync log entry added
